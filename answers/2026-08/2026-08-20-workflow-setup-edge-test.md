ChatGPT Pro 回答（原文）

我理解这套长期工作流如下：

每次收到问题后，Codex 先在不查看 ChatGPT 回答的情况下独立作答；随后通过 Edge 打开 ChatGPT，将同一原问题原样提交，并且只有在界面明确显示所要求的 **Pro 模型标识** 时，才把该回答记为“ChatGPT Pro 回答”。之后把原问题、两份独立回答、模型标识、时间和执行状态整理为 Markdown，提交并推送到公共 GitHub 仓库。必须确认远端提交存在且公众能够访问后，才能通知“可以让别人查看”。

首次设置必须包含这些规则和保护：

1. **固定工作目录和文件结构**：在 `D:\wuying\wuying_codex` 中保存脚本、Markdown 记录和配置；凭据、浏览器数据、临时文件与本地配置必须通过 `.gitignore` 排除。

2. **保证两份回答相互独立**：Codex 完成并封存自己的回答后，才能调用 Edge；不得根据另一方回答修改、补写或伪装成独立结果。原问题应原样保存，必要的系统说明另列记录。

3. **严格验证模型身份**：只能记录界面实际显示的模型名称，不根据订阅、URL 或经验推测。若未显示 Pro、模型切换失败、页面异常或无法读取标识，应标记失败并停止发布，不能把其他模型写成 Pro。

4. **公开前进行敏感信息检查**：不提交密码、令牌、Cookie、会话信息、个人隐私、私有仓库内容或未获授权的专有代码。发现风险时，应中止提交并生成经过脱敏的公开版本，而不是直接上传原文。

5. **以远端验证作为成功标准**：本地生成文件或本地 `git commit` 都不算完成。必须确认 `git push` 成功、远端分支包含目标提交，并验证公共仓库页面可以访问；任何认证失败、网络失败、冲突、推送被拒或仓库仍为私有，都不能通知完成。

“开始设置，并且调用 Edge 试试”应被理解为：建立上述目录、模板、忽略规则、敏感信息扫描和推送验证机制，并进行一次 Edge 联调测试。所有尚未实际验证的 GitHub、浏览器或模型操作，都应明确记录为“待执行”或“失败”，不能声称已经完成。
